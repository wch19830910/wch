# 知乎（去广告与页面净化）

[安装模块](https://raw.githubusercontent.com/wch19830910/wch/main/Surge/AdBlock/Zhihu.sgmodule)

以 zirawell 的原生 Surge 知乎规则及 RuCu6 来源的净化逻辑为基础，整理成单一响应脚本，修正兼容问题，并保留正常账户数据和消息通道。文件名采用 `Zhihu.sgmodule`，Surge 内显示中文名称。

## 功能与默认行为

- 处理开屏、首页横幅与悬浮广告、推荐及关注页广告、热榜合作推广、回答和文章页推广、评论区顶部广告。
- 精简搜索填充词、搜索推荐、部分相关内容推广及广告配置。
- 默认保留普通视频、直播、付费和盐选内容；带明确广告或营销标记的项目仍按广告处理。
- 保留真实会员状态、会员卡片入口、关注关系和通知计数；不加入本地伪会员、关键词黑名单、签到或付费内容解锁。

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `hideVideos` | `0` | `0` 保留普通视频与直播；`1` 在支持的信息流和回答列表中隐藏可识别的视频与直播项目。 |
| `hidePaid` | `0` | `0` 保留付费和盐选内容；`1` 隐藏可识别的付费回答、盐选推荐项目。此选项只隐藏条目，不解锁内容。 |

在 Surge 的模块参数设置中修改后保存。参数只处理服务器返回且能识别的项目，不能恢复 App 已经不提供的栏目。

## 安装

需要 Surge iOS 5.14.2+ 或 Surge Mac 5.9+。在 Surge 的模块页面选择从 URL 安装，粘贴上方地址并启用。安装并信任 MITM 证书，开启重写、脚本及 MITM，完全退出知乎后重新打开。相同 App 只启用一份净化模块。

MITM 使用七个明确知乎主机，补齐回答详情处理所需的 `page-info.zhihu.com`。保留上游用于处理 HTTPDNS 的精确 IP 拒绝；未加入整个知乎域名的拒绝或泛域名 MITM。

## 相对原始规则的调整

- 把重复名称的响应入口整理为一个入口，脚本由本仓库发布，不再直接运行未修正的上游 JavaScript。
- 修复旧脚本中的变量引用、悬浮图标清理及配置路径判断问题；对缺失字段、未知结构、无效 JSON 做保留原响应处理。
- 不再一概删除普通文章、内容卡片、提示字段；视频和付费内容过滤由参数控制，默认关闭。
- 不拦截 `mqtt.zhihu.com`，保留消息长连接。不拦截通知计数，也不清空 `me/guides` 或会员卡片接口。
- 不直接清空整类视频榜单；视频开关仅控制本模块支持的响应列表，不是全局视频屏蔽。
- 省略作用范围超出知乎的 `AVOS*` 全局 User-Agent 规则及共享 SDK 域名拒绝。
- 将 Map Local 的 JSON 响应写成 Surge 支持的 text 加 JSON Content-Type，脚本响应大小设置为 `-1`。

这是保留正常功能的整理版，不宣称逐条照搬原始“全净化”。正常消息能否送达还取决于 App 和系统通知设置；保留通道不等于对推送送达的保证。

## 远程更新

- GitHub Actions 的 **Update Zhihu** 每 6 小时检查上游模块及原脚本。
- 已审核的配置范围内发生变化时，通过构建和测试后发布；新增接口、未知配置或原脚本内容变化时，先停止发布，待兼容审查后接入。
- 原脚本采用已审核 SHA256。这个版本包含参数和修复，不会直接覆盖成未经审核的新上游脚本。
- Surge 每 24 小时检查本仓库的 `Surge/Script/Zhihu.js`；模块本身按 Surge 的远程模块机制更新。可手动更新模块及外部资源获取最新版。
- 下载、兼容或测试失败时保留上一次已发布成品。GitHub 定时运行可能延迟，公开仓库连续 60 天无活动时可能需在 Actions 重新启用。
- 修改 `#!name`、`#!desc` 或默认参数，请编辑 `Surge/scripts/build-zhihu.mjs` 后运行对应工作流。只编辑自动生成的模块会被下次同步覆盖。
